# Mini 基础验证发现的启动参数拒绝

在 `d161700a` 的本地重编译包上，Mini 已正常进入经典首页，首次 Wine 启动也完成运行时更新和图形预检，但随后报告“Wine 启动请求未被接受”。

原因是新深度兼容设置始终显式传入 `WINEHUA_DXVK_D24_STORAGE_D32=0/1`，而 `launchClient` 第 13 项参数仍只接受原 CPU 设置白名单，导致请求在创建启动线程之前被拒绝。与系统 NCP、签名或 JIT 无关。

修复保留 CPU 校验函数及已有参数布局，新增受限的启动环境校验：接受原 CPU 白名单和深度开关的精确 `0/1` 值，继续拒绝其他图形变量、preload、换行、额外参数和无效开关值。该设置仍只在新会话捕获，不改变默认关闭策略。

CPU/启动环境的可执行回归加入 `make test-hsl-pr78`，覆盖默认关闭、显式开启以及非法输入。实际安装包身份和修复后的基础验证另行记录。
