# 《战舰世界》Steam 启动早退与 2.0.7 测试

按用户最新反馈，可运行的历史版本未知，1.4.6 也可能遇到该问题。以下判断来自 2.0.6（2000060）的实际日志。现有导出覆盖 11 月 13 至 20 日，其中五天保留了 16 次可按宿主 PID 配对的游戏创建、退出记录，存活时间为 1.08～2.13 秒。

| 本次核查 | 结果 |
| --- | --- |
| 最新一次派发 | 11 月 20 日 20:13:25 云同步完成。Steam 启动 AppID 552990 的 `WorldOfWarships.exe -dx11`。Windows PID 684、宿主 PID 24351。宿主从 20:13:27.847 到 20:13:29.660 共 1.813 秒。游戏主线程 688（02b0）进入 `RtlExitUserProcess(1)`，宿主随后记录 `libc-exit status=1`，Steam 回收 PID 684 时同样记录退出码 1。这段时间新建的三个 Wayland surface 都属于 Steam 宿主 PID 23131。 |
| 辅助进程 | 游戏和 `x64launcher.exe` 均由宿主 PID 23131 发起。11 月 14、16 日可见辅助进程返回 0，游戏随后返回 1。 |
| 渲染、CPU | 11 月 16 日的 Zink 会话和 20 日的 DXVK 1.10 会话都有早退。最新一轮可归属游戏的 60 条 FEX 对齐事件均记录了 `handled=true`。导出的 DXVK 日志主要来自 Steam 界面等其他进程。 |
| 其他线索 | 游戏主线程出现 Kerberos 初始化告警。Wine 在该分支打印告警后可继续完成认证包注册，日志也记录了同一线程继续执行。11:53 的 Steam 手柄配置断言在 20:13 这轮未出现。导出只含当日 Wine stderr 末尾 256 KiB，启动早段及游戏自己的错误说明仍缺失。 |
| 历史包内容参考 | 10 月 10、11 日两份 1.4.6 发布包中的 x64 FEX、原生 NTDLL、x64 DXVK 1.10 的 D3D11/DXGI 校验值分别一致。两个 Windows 系统模块目录共 1413 个文件名在 2.0.6 RC 中均有对应成员。二进制差异只能用于缩小排查范围，目前缺乏历史成功与失败的同条件对照。 |

当前托管 Steam 入口会显式指定客户端工作目录。2.0.6 的 Wine OHOS 派生路径从父 Unix 环境复制该设置，忽略了本次 Windows `CreateProcess` 已打开的目录。Win32 启动参数另经 wineserver 传递，这个缺陷影响子进程原生侧的工作目录和相对文件访问。本次日志没有记录游戏实际尝试打开的资源，因此尚不能确认游戏退出由此触发。

2.0.7 使用 Wine 为本次创建打开的目录，从目录描述符解析原生路径，通过现有进程代理传给子进程。解析失败时丢弃旧启动器目录，子进程可回退到可执行文件所在目录。主机测试使用真实 Unix 套接字、目录描述符和含空格路径，覆盖独立子目录、无目录、父进程环境保留和句柄回收。另将可恢复的对齐信号改为有界摘要，保留其他信号的诊断额度。

**用户复测**　保留已有 Wine 数据，在原有 Steam 库中用 DXVK 1.10 启动同一游戏，记录是否显示首窗、进入港口，以及正常退出后能否再次启动。如仍秒退，请在当次失败后立即导出旧柚日志，有生成时附游戏安装目录下同一时间的 `profile/python.log`。

**测试包**　2.0.7（2000070）ARM64，代码提交 `2d42c2b4`。两个包均已通过 SDK 验签。内测 HAP 的 332 个业务文件与签名前逐一比对 SHA-256，通过 52 项运行时成员检查。AGC 邀测 APP 内的 HAP 已与同一输入逐项核验，`pack.info` 按 JSON 内容核验。本次没有游戏副本，进入港口及退出重启仍待复测。
