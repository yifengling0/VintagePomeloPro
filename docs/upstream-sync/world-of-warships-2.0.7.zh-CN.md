# 《战舰世界》Steam 启动回归与 2.0.7 测试

用户反馈 1.4.6 可运行。现有导出覆盖 11 月 13 至 20 日，其中五天保留了 16 次可按宿主 PID 配对的游戏创建、退出记录，存活时间为 1.08～2.13 秒。缺少同一游戏构建在 1.4.6 的启动日志。

| 本次核查 | 结果 |
| --- | --- |
| 最新一次派发 | Steam 已完成云同步，启动 AppID 552990 的 `WorldOfWarships.exe -dx11`。Windows PID 684、宿主 PID 24351。在 1.81 秒后 Wine 与 Steam 都记录退出码 1，未见游戏自有窗口。 |
| 辅助进程 | 游戏和 `x64launcher.exe` 均由宿主 PID 23131 发起。11 月 14、16 日可见辅助进程返回 0，游戏随后返回 1。 |
| 渲染、CPU | 11 月 16 日的 Zink 会话和 20 日的 DXVK 1.10 会话都有早退。最新一轮可归属游戏的 60 条 FEX 对齐事件均记录了 `handled=true`。导出的 DXVK 日志主要来自 Steam 界面等其他进程。 |
| 两份实发 ARM64 HAP | 1.4.6 与 2.0.6 RC 都带 x64 FEX、NTDLL、MSXML 和 DX11 运行库，二进制内容有变化。按成员名比较，旧包 `bin/aarch64-windows/` 和 `bin/i386-windows/` 中的文件均能在新包找到。1.4.6 发布记录注明构建时存在本地修改。 |

1.4.6 之后引入的托管 Steam 入口会显式指定客户端工作目录。Wine 的 OHOS 派生路径从父 Unix 环境复制该设置，忽略了本次 Windows `CreateProcess` 已打开的目录。Win32 启动参数另经 wineserver 传递，这个缺陷影响子进程原生侧的工作目录和相对文件访问。旧日志没有记录游戏实际尝试打开的资源，因此尚不能确认游戏退出由此触发。

2.0.7 使用 Wine 为本次创建打开的目录，从目录描述符解析原生路径，通过现有进程代理传给子进程。解析失败时丢弃旧启动器目录，子进程可回退到可执行文件所在目录。主机测试使用真实 Unix 套接字、目录描述符和含空格路径，覆盖独立子目录、无目录、父进程环境保留和句柄回收。另将可恢复的对齐信号改为有界摘要，保留其他信号的诊断额度。

**用户复测**　保留已有 Wine 数据，在原有 Steam 库中用 DXVK 1.10 启动同一游戏，记录是否显示首窗、进入港口，以及正常退出后能否再次启动。如仍秒退，请在当次失败后立即导出旧柚日志，有生成时附游戏安装目录下同一时间的 `profile/python.log`。
