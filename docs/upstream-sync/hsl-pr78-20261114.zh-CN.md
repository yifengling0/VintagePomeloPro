| 修复 | VPP 实现与边界 |

## 已存在、保留与暂缓

- VPP 已有 inline upload、dirty generation、coverage sort、direct fence wait=0，以及部分资源 FD/device 释放修复；HSL 对应内容有来自 VPP 的同步，不重复覆盖。
- PR 的 cached repaint/EGL 生命周期和进程回收部分，VPP 已有相应或更完整实现；保留现有 self-pipe reaper，未引入周期轮询。
- 已选新 Wine 中已有 IME scan-code lParam 和 DirectDraw 裁剪修复，未把旧 Wine 文件覆盖到候选源码。
- HSL event 等待的实测结果更慢，因此没有改成默认 event，也未全局强制 inline profile。
- HSL 空 Wayland commit 的 viewport 重采样属于其独立 compositor；VPP 实现不同，没有复制整个 compositor。
- HSL GNU WSI/rootfs、Pulse/PipeWire、软件中心及 Linux FEX thunk 不直接用于 VPP 的 OHOS Wine 路线，本次未复制这些组件。
- SNORM→FLOAT 的数值范围/量化缺口仍未解决，本轮没有宣称修复。HSL 古墓 R41 画面反馈只适用于 HSL；其带 trace 的约 19.4 FPS 和未完成退出验收不能外推 VPP。
