# 2.0.2 修复与未签名构建

版本为 `2.0.2 / 2000020`。本次包含手机 Wine 进程创建路由修复、最终运行库保护，以及经典界面初始化阶段和累计秒数恢复。HmosDeck 的启动画面保留原实现。

手机进程入口改为应用自有的 hidden `WineHua_*NativeChildProcess`，避免 SDK 同名符号先加载时绕过 phone-fork。打包保护拒绝仍覆盖 SDK 符号的旧宿主。定位、宿主回归、最终 ELF 检查和 M80 真机结果见 [手机初始化记录](phone-initialization-2.0.1.zh-CN.md)。

本版本沿用 Wine `098ece0eedff40bea426d2d57b215bb81411e239` 与 FEX `c3b2b2306347e16da04e512a52432cb9c921d221`，不会回退到旧子模块载荷。完整组件来源和重建方式沿用 [2.0.1 组件选择](release-2.0.1.zh-CN.md)。最初交付的 2.0.2 未签名包保持当时的 37 项运行库锁；其后本分支加入 [HSL / PR78 图形同步](hsl-pr78-20261114.zh-CN.md)，当前发布锁为 40 项，单独记录新图形组件的主机验证边界。不能把最初交付包视为已包含后续图形修复。

本地和 CI 共用正常未签名构建入口：

```sh
export NATIVE_ARCH=arm64-v8a WINE_ARCH=aarch64 GUEST_ARCH=aarch64
bash scripts/package.sh hap-unsigned
```

已有运行库暂存必须完整通过发布锁，来源不符则失败。本轮复用同一 source-integrity 增量检出，按照逐文件 SHA-256 清单同步权威工作区中的源修改，再正常编译和打包。交付清单记录基线提交及未提交源修改的 SHA-256，不能仅用基线提交冒充完整的已提交状态。

M80 的冷初始化、实际 JIT 申请、阶段读秒和强制退出后重启，已用相同宿主及界面代码的 2.0.1 真正 debug 签名测试包验证。2.0.2 未签名包没有安装到用户当前正在操作的手机上，也不代表 AppGallery 签名版本已完成手机验收。本次不触发线上 CI、不生成 APP、不移动历史标签。
