# Game 侧栏、系统模式开关与 Steam 启动修复

本文为当时未连接设备的历史检查点。后续 Mini 安装、Steam 派发游戏与退出验证见
[2026-11-18 真机评价](steam-game-mode-evaluation-20261118.zh-CN.md)，不再以本文“未安装”描述当前状态。

## 本轮范围

基于 `feature/gamescope-port@b3dc9fc3`，产品变更分为：

- `0473f0ec`：游戏内右侧画面控制栏、即时缩放/锐化/限帧、系统设置中的持久化 Game 开关。
- `c5a9b77e`：Windows Steam 的实际窗口就绪、启动错误传播及客户区呈现。

本轮不操作 Mini，不改版本，不合并 main、不推送、不替换 2.0.4 正式包。
用户已认可上一包的 PAL4 性能，保留该包作回退，不追加低电量性能测试。

## 最终行为

1. 系统设置 → 显示 → Game 模式。默认关闭，保存后即时切换游戏库界面，并在下一次
   启动应用时恢复。Classic/Console/Deck 的原选择保留。活动游戏和 Steam 未正常结束时
   拒绝切换，不强制结束进程；Wine 呈现路线仍按既有会话冲突规则处理。
2. 移除首页及 Deck 的 Game 快捷切换入口，删除不再使用的独立 GameSettings 页面。
   游戏库的设置入口直接进入系统设置，空库文案与手柄导航不再指向被隐藏的入口。
3. 游戏内控制覆盖为右侧深色面板，窄屏自适应、内容滚动，支持触摸、键鼠和手柄。
   画面控件直接读取当前原生会话策略，包括每游戏覆盖，而不是全局默认值。
4. 缩放（线性、最近邻、整数、FSR 1.0）、FSR 锐化、默认/30/60 FPS 即时应用。
   仅改变原生原子策略，逐帧图像仍在原生层。静止场景也会因策略变化重画；限帧变化
   会刷新生产者节拍，不必等待屏幕刷新率变化。暂停/EAGAIN 不消耗待呈现的变更。
5. 即时参数保存到当前游戏的独立画面设置，不改全局默认。一次只进行一个写入，并仅
   保留最新待存值，避免拖动滑块产生无界写入队列。失败有提示；会话世代变化时拒绝
   旧面板写入。独立图形后端和 Game 呈现开关不做运行中热切换。
6. 性能浮层显示仍可即时开关；保留游戏回库和正常退出走原有生命周期与输入通道。

## Steam 诊断与修复边界

源码可确认旧行为先显示 Wine 桌面，再准备 Steam 依赖和派发进程；拿到 PID 即完成
启动提示，延迟启动队列还会吞掉准备错误。Steam 客户端被排除在 Game 客户区呈现之外。
这些会造成空桌面被当作启动完成，或实际错误落在桌面后方。

现在保持启动反馈，45 秒内等待受管理 Steam 安装的真实非桌面窗口，按进程、会话与
窗口身份关联。允许 bootstrap/URI 命令发送进程退出后由真正客户端接管，也支持已经
运行的客户端；不按标题判断，不将同路径复用 PID 的旧窗口视作新进程窗口。
窗口就绪后恢复现有承载窗口并呈现 Steam 客户区。用户在等待期间明确导航，则不抢焦点。
准备失败、会话停止、显示失败或超时会返回明确原因；超时不杀进程、不重置 prefix。

这属于本轮源码修复，尚未取得本次 Steam 失败的设备日志，不能据此宣称 Mini 上的
Steam 客户端已成功启动、登录或派发游戏。慢网络/CEF/安装完整性若仍失败，需要在
充电后按实际错误继续定位。

## 主机验证

- `make test-game-presentation`：动态策略、静止画面重画标志、生产者限帧、整数几何与
  输入逆映射，保留默认 120 display ticks 及显式 60/30 的原判据。
- `make test-game-mode-models`：会话策略/回退、实时更新、每游戏初值、原生拒绝、旧面板
  隔离、目录模型、输入和 AppSession。Steam 用例覆盖冷启动不显示空桌面、依赖错误、
  假标题、bootstrap 换 PID、warm 复用、用户导航、超时、停止和回收 PID。
- `run_configuration_unit_tests.cjs`：33 项集成场景通过，新增 Game 开关和每游戏策略在
  其他偏好更新、保存及重载之后保留的判据。
- `run_steam_client_selection_tests.cjs`、`run_windows_steam_deck_tests.cjs`、
  `run_deck_launch_feedback_tests.cjs`：Windows 客户端六类操作、busy/失败重试、窗口等待、
  原卡片路由、手机/平板布局及启动反馈通过。
- `make gamescope-app-native`：OHOS ARM64 增量编译通过；ArkTS/HAP 编译通过。

没有宣称全仓库测试通过：旧 `run_host_window_task_tests.cjs` 仍调用当前基线已不存在的
Linux Steam 接口 `expectSteamGame` / `setSteamGameCloser`，运行失败。本轮没有恢复已撤销
的 GNU Steam 路线，也没有删除这些旧测试来伪造通过；本轮 Windows 会话/窗口行为由上面
实际服务测试覆盖。构建仍存在原有 SDK 弃用警告。

最终调试包身份、签名与原生载荷比较写入固定任务目录的 `package.json`、
`package-audit.json`、`sidebar-delivery.json`。构建复用原 Gamescope core、Wine/FEX 和客体
图形载荷；不因界面修改重编完整运行时。
