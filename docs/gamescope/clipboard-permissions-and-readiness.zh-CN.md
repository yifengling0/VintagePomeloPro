# 剪贴板授权与 Gamescope 剩余范围

本轮在 `feature/gamescope-port` 实施，不升级版本、不合主分支、不推送、不替换正式 2.0.4 包。

## 剪贴板接入

既有 X11 selection 与 Wayland `wl_data_device_manager` 文本桥继续复用。系统与 Wine 的文本
同步共用 `X11ClipboardService`；Game 页面及同进程 Gamescope 不再建立一条剪贴板通道。

- 声明受限用户授权权限 `ohos.permission.READ_PASTEBOARD`，提供中英文用途说明。
- 有活动 Windows 会话、前台 Ability 且剪贴板包含文本时才申请授权；已授权只检查状态。
  单次会话拒绝后不重复弹窗。权限异常或拒绝不阻止 Wine 启动，也不阻止 Windows 向系统复制。
- Entry/Desktop/WineWindow Ability 统一上报前后台；切换窗口按 Context 身份转移读取所有权，
  后台停止读取。权限弹窗未结束时暂停 Windows 向系统写入，避免覆盖待粘贴的系统内容。
- 读取有效期 1 秒；最多保留 4 个尚未完成的平台读取，超时后仍计入上限直到真实完成，
  超限只保留最新重试。旧会话、旧焦点和过期异步结果不得发布。原有单份文本上限与原生
  传输资源上限保留；仅支持文字。
- 触摸键盘旁增加“复制”，通过现有输入所有权发送 Ctrl+C。安全 PasteButton 继续先同步并
  确认 Wine selection，再发送 Ctrl+V；持续读取权限被拒时仍可使用其临时授权。

三份新 Profile 已用 SDK 验证签名、包身份、有效期及剪贴板/可写代码 ACL。正式与内部测试
Profile 对应原正式证书；新调试 Profile 对应本机既有 HSL 调试证书。专用构建配置配对其
实际证书链、密钥和材料；旧调试配置保留，正式包未重新签名。签名材料不进 Git。
新调试包签名身份与此前候选不同，不能假定可以直接覆盖安装；后续设备操作须先检查身份，
保留应用数据，不能为绕过签名冲突直接卸载。

主机行为测试覆盖授权、拒绝与临时粘贴、文本类型检查、后台和窗口切换、4 个读取上限、
超时、乱序、跨会话、串行写入。原生 Wayland 生命周期测试使用 ASan/UBSan。
设备权限弹窗、跨应用中文/空文本复制粘贴、实体键盘与触摸入口仍待 Mini 和手机分别验收。

## 颜色和卡顿的状态

SDR 编码、RGBA8 中间纹理、FP16 能力选择及 storage 交换链直接输出已经实现，相关实际
shader 主机测试和失败回退测试已通过。默认档固定 60 FPS 的额外上限也已移除。
Mini 断连后尚未验证这些新包，不能宣称设备颜色和卡顿问题都已解决，也没有新增 FPS 收益
结论。PAL4 既有 Zink 白地面问题仍单列。

## Gamescope 尚缺的内容

| 项目 | 当前边界 | 下一步 |
| --- | --- | --- |
| X11 Game 客户区融合 | 专用最终裁切与对应输入映射尚未完成 | 完成 X11 接线，验证弹窗、黑边及焦点 |
| GPU 桥与输出 | NativeBuffer/fence、退役、FSR、直接交换链输出已实现 | Direct/Venus/VirGL 与 Zink 分别验画面、同步及退出重进 |
| 手机 | 同进程路线已接入，不依赖 NCP | 手机真机验证输出、旋转、触摸、IME 与权限 |
| Game/Steam 会话 | 游戏库、快捷面板、覆盖设置与返回逻辑已有代码和定向测试 | Steam 派发、退出返回、设置冲突做真机确认 |
| 画面和帧节拍 | SDR/FSR shader 与默认/30/60 策略已有主机证据 | Mini 验颜色、FSR 画质与实际 VSync、游戏 FPS |
| 稳定性和性能 | 新 GPU 链尚无完整设备数据 | 5 轮启退、3 轮 resize、后台恢复、异常退出、资源增长；PAL4/Heaven/DX11 同条件 3×60 秒 |

优先让 Mini 的 PAL4 在相同后端、渲染及输出尺寸下，对照普通 Wayland 与 Game 默认档，
核对用户报告约 120 FPS 的存档场景。FSR 降低游戏分辨率后的结果单独报告。
