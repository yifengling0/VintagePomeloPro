## 已验证的设备链路

USB 平板 MLR-AL10 使用开发签名 rc14。真实华为 Push v3 返回 `80000000` 和 requestId 后，已在系统通知栏看到“旧柚 VIP 提醒测试”。第二次测试先强制退出应用，再发送并实际点击通知，冷启动进入系统设置的账号与同步、会员区域展开；服务端该条 delivery 记录 `accepted=true`、`opened=true`、`displayStatus=OPENED`。通知明确说明是测试且不会扣款，未虚构续费金额。

系统通知设置可直接由会员页打开。关闭“允许通知”并返回后，会员页出现开启提醒提示，云端有效登记设备为 0；恢复允许通知并点击开启提醒后，有效登记设备恢复为 1，页面显示已开启。最终保持通知开启。设备截图、布局、账号与 token 仅留本机证据，不提交仓库。

## 已实现的逻辑

- 下一期时间、金额与币种来自官方签名订阅状态。提前 7 天进入提醒窗口，每天北京时间 16:05 扫描一次；按每日扫描相位，正常最迟在预计续费前 6 天、可能提前一天扣款前 5 天发送。
- 未到提醒窗口的任务跳过支付平台查询；发送前重新官方验签，取消、撤销、退款或扣费重试不发送。已发送周期去重，等到官方续费时间再发现下一周期。
- 持久化设备、周期、发送租约、发送受理与打开状态；失败保留记录并告警，冷却至少 15 分钟后由下次每日扫描重试。异常、离线、通知关闭等情况不保证实际展示，不能仅凭接口受理认定送达。
- 每日任务的心跳容忍 36 小时，超时阻止新的正式自动续费购买；恢复购买、查询和取消入口不受此限制。
- 沙盒提醒与沙盒购买单独控制。官方 receiptId 为可选发送参数，沙盒真实发送可先行验证；NORMAL 仍保留回执及正式验收门槛。
- 冷启动通知导航使用 Ability 窗口的 router，首次 loadContent 后延迟一个 UI 周期并有界重试，实际通知点击已验证。

本轮修复了 Push 服务账号鉴权：控制台项目级公钥应登记 SPKI DER 的裸 Base64，不能粘贴 PEM 头尾。当前新 key 已真实发送成功；密钥不在源码、ZIP 或客户端内。AGC 单个环境值有长度限制，RSA 私钥使用三个 Base64 段还原，缺段或与完整私钥配置冲突时拒绝启动。

## 调度与回执的验收边界

按照用户要求，现将 `$latest` 的 timer 临时替换为无依赖的日志诊断包 `vp-timer-smoke-v2-20261017.zip`，删除每日触发器，保留 `vip-timer-smoke-minute`：`@every 1m`，启用。该函数不访问会员、数据库或 Push。16:35:48（北京时间）手动调用成功，AGC 平台 logger 中出现 `VP_TIMER_SMOKE` 与 `MANUAL_BASELINE` 标记。16:40:35 将此诊断触发器从异步改为同步调用；查询至 16:42:43 仍仅有上述手动日志，自动调度仍待确认。诊断期间 timer 不承担续费提醒发送。

已在线复核官方《定时触发器》《创建并配置函数》《event对象》《Node.js》文档。文档示例为 `@every 1m` 或 `cron(* * * * *)`；后台原始记录确认 Every 表达式、启用状态和 `$latest` 绑定均正确。通过控制台使用的更新接口尝试文档的 `cron(...)` 写法，后台返回 HTTP 400 / `101212: schedule is invalid`，配置未改变。此结果说明文档写法与当前后台校验存在差异，尚不能确定自动调度失败的根因。

原诊断代码使用 `console.log`，未出现在 AGC 业务日志中；现按 Node.js 官方文档使用函数第四个参数 `logger` 或 `global.logger`，手动调用的业务日志已确认可见。自动日志必须具有 `SCHEDULED_TRIGGER` 标记；手动调用不能替代自动调度验收。此前生产逻辑最后一次心跳仍来自北京时间 15:03 的手动调用。

官方送达回执尚未部署公网接收入口，未配置 receiptId；当前 `providerDeliveryResult` 为空。实际通知展示和用户点击均已有独立设备证据，但不能当作华为官方回执。AGC 当前可新建的 HTTP 触发器仅有 API 客户端鉴权，Push 回调不能携带该令牌。已交付最小 FunctionGraph 回执包，未创建固定费用 APIG 专享实例，也没有独立服务器。

ACCOUNT 通知权益在控制台已核对获批。NORMAL 支付、正式备份验收及真实跨周期续费仍未完成，正式新购未开放。测试设备现有订阅均处于已关闭或撤销状态，不会为验收伪造一个真实扣款任务。
