# 1.4.8 账号重启与自动同步修正

分支 feature/account-cloud-membership-mvp，版本 1.4.8 / 1004080。开发签名测试交付，不正式发布；未改后端商品、云函数实现或任何运行时。

## 根因与变更

1. 原 ValueAddedService 的内部会话仅内存保存，启动时没有恢复流程。现在仅持久化“恢复登录”的布尔意愿，使用 Account Kit forceLogin/forceAuthorization=false 重新核验已授权的设备身份、交换新的短期服务器会话，再恢复未完成和当前订阅。不保存账号令牌、订单令牌或本地 VIP 标记；显式退出关闭恢复。已有账号 journal 只作为首次迁移恢复意愿，不能证明账号身份或权益。
2. 初始化、静默恢复和购买恢复分别合并并发调用；绑定账号代次。旧会话到期后前台队列可恢复，暂时连接错误自动重试。旧账号的延迟结果不能写入新账号状态。
3. 以前单笔旧订单核验失败会跳出恢复循环，并让自动备份在权益查询之前失败。现在逐笔隔离失败，继续核验当前订单；是否允许上传仍独立取决于服务端核验的有效会员。错误的旧订单不授予权益，也不阻止真实有效的新订单备份。前台至少每 60 秒复查未完成/当前订阅，处理新续期与确认重试。
4. 权益请求合并；核验订单后使旧请求失效，旧响应重新取新权益；界面增加请求代次和账号监听，避免晚返回的旧结果覆盖新状态。本期到期先查询后续权益再展示开通入口，不重复购买已付费本期。
5. 正常本地保存后立即标记“等待备份”，700 ms 合并自动执行；同步过程中再修改会排队下一轮，不能把旧快照上传成功当整份最新修改完成。页面是否打开不影响触发。

## 普通取消与本次真实沙盒状态

官方定义 status 1=生效、2=到期、3=尝试扣费、5=撤销；autoRenewStatusCode 0=不续费。status=1、autoRenew=0 且官方 expiresTime 尚未到期继续 VIP；普通取消不会截短已付费期限。撤销/退款不能因为 expiresTime 仍是未来而重新授权。

本次只读实际 CloudDB 和官方 subscription/status/query，并验证官方返回 JWS。两笔记录复查均 status=5，另一笔旧保护回执出现 ORDER_BINDING_MISMATCH，但其查询返回的官方组状态也为 5。核验过的状态字段中没有撤销时间/撤销原因，无法据此断言用户操作退款、未确认导致退款或沙盒自动结束；撤销具体原因尚未确定。一个订单 finishStatus=1，另有 finishStatus=2，不能把所有撤销均归结为未确认。

旧绑定错误仍被安全拒绝，本次没有修改 HMAC 所有权校验或将官方撤销改为取消续费。当前账号无可确认的有效沙盒权益，因此备份暂停符合服务端状态。
