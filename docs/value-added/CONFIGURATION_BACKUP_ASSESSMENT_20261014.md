# 完整应用配置备份评估

Z 盘是应用拥有的 Download 目录在 Wine 中的映射，保留游戏文件，但并不保存全部应用配置。

| 内容 | 实际存储 | 当前云备份 |
| --- | --- | --- |
| 游戏文件、Steam 客户端、steamapps | Download/Z 盘 | 不上传 |
| 按键布局、方案鼠标速度、手柄映射 | vintage_pomelo_input_profiles / profiles_v6 | 完整 v6 方案已上传 |
| 外观、卡片布局、全局默认方案 | vintage_pomelo_pro / global_settings_v1 | 当前仅白名单 7 个配置字段 |
| 全局虚拟鼠标、按键透明度、手柄输出/死区、控制条位置、Wine 语言与显示设置等 | 同一 global_settings_v1 | 当前未上传 |
| 每游戏方案绑定、启动/兼容参数、收藏、自定义名称、显示模式等 | vintage_pomelo_pro / app_settings_v1 | 当前未上传 |
| 自定义封面、背景图 | 配置路径及对应图片文件 | 当前未备份文件，路径不能代替图片内容 |
| 游戏存档、Wine prefix/注册表、Steam 登录信息 | 各自游戏或运行时目录 | 存档功能按要求保持撤下 |

来源：AppSettingsStore.ets 的存储常量与保存接口；InputProfileService.ets 的 profiles_v6；AccountSyncModels.ets 的 preferencesPayload；AppModels.ets 的 GlobalSettings/AppSettings。

现在的缺项主要是全局配置范围与游戏绑定，而非方案内按键字段。游戏目录即使仍在 Z 盘，应用沙盒卸载后也无法凭游戏文件恢复这些设置。

## 建议：统一的版本化配置快照

界面收敛为“自动备份应用配置”，一个状态和最后成功时间。内部包含全局配置、全部输入方案、每游戏配置及其方案绑定、必要图片资源引用；逻辑上一次提交，一致地恢复。底层可复用现有 CloudDB、哈希和 CAS，但需由一个已发布的快照版本指向所有完整成员，不能几个成员各自写入成功就宣称整份备份成功。

不直接复制整个沙盒/XML。vintage_pomelo_pro 同时包含 API key、缓存、游戏目录、运行记录；沙盒还有登录状态、同步 journal 和运行时文件。全量覆盖会将账号凭据、旧路径、旧 schema 与当前账号同步基线一起恢复。应通过正常存储服务导出、校验、迁移和恢复配置。

恢复顺序：完整下载校验 → 保存当前配置和恢复事务 → 恢复全部方案及 ID → 恢复全局配置 → 匹配每游戏配置与方案绑定 → 发布完成状态。中断后继续或回滚；不能出现绑定指向不存在方案，不能覆盖恢复期间本地新修改。

所有 GlobalSettings/AppSettings 字段须逐字段制定恢复规则。arguments 支持 Unicode，不执行参数内容；executable/workingDirectory、图片路径、prefixId 等不能盲目应用。有效同机目录可复用，Download 内目录用相对根路径；缺少图片、容器时保留待匹配引用。设备能力与性能配置恢复前需验证；未知新字段不能静默丢弃后反向覆盖云端。

## 游戏身份、删除和范围

当前普通卡片 ID 是 source + 规范化完整路径的 FNV 哈希（stableAppId）。同路径重扫通常稳定，移动目录、改变入口 EXE 或重选游戏根目录会改变身份。完整备份需额外保存来源、库内相对入口、可验证文件身份等。优先精确匹配，有歧义时保留未匹配配置，不靠名称猜测并套用兼容参数；已匹配的同机游戏不要求逐个重新选择方案。

本机删除游戏只移除本机卡片及适用绑定，云端配置保留供重装恢复；再次复制并精确匹配后恢复。方案删除不得被定时同步复活，相关游戏回退默认并保留删除标记。明确“删除云端备份”才删除备份，不把拔出存储或目录暂不可访问当永久删除。

游戏配置与游戏存档是两件事；存档备份继续不开放。Steam 下载文件、Steam Cloud 存档、登录凭据和整个 Wine 容器不纳入配置快照。

本次仅评估完整配置快照，先修复现有账号恢复、购买恢复与同步触发。当前 HAP 尚不能恢复每游戏设置或全部全局设置。后续实施需一起修改快照 schema、服务端校验、迁移、恢复事务和正常保存触发，并验证卸载重装、游戏重扫/移动/删除、缺资源、断网中断及新旧版本互通。
