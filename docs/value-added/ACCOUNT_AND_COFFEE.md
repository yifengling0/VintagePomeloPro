# 华为账号与咖啡配置

## 登录与云同步分开

账号页直接调用 Account Kit 的 `createLoginWithHuaweiIDRequest`，校验随机 state；登录后再申请 `profile`，从 SDK 的 `avatarUri`、`nickName` 展示头像昵称。拒绝头像授权不取消已成功的身份登录。退出时清除本次头像、昵称和会话，不将 SDK 凭据或头像链接写入日志。

基础华为登录不以 `value_added_config.json` 或 `/v1/capabilities` 为前置条件。2026-10-13 已用现有官方开发 profile 真机登录成功；包名 `com.vintage.pomelopro`，profile 的 appIdentifier 为 `6917605913989898754`。

业务云仍使用服务器换码得到的会话，不能用客户端 OpenID 直接访问账号数据。未配置后端时显示“华为账号已登录 · 等待云同步连接”。云函数/CloudDB和真实云会话已接通；OBS和云存档传输尚未验收，配置见 `AGC_SETUP.md`。

## 咖啡沿用旧柚

入口为系统设置独立“赞助”，默认收起，展开后自动检查原未完成订单；账号与同步不再显示咖啡。原卡住的咖啡订单已在真机核销，后续查询无待确认订单。

参照旧柚仓库 `e3a5cda9` 的 `app/entry/src/main/ets/pages/About.ets`：一个消耗型商品，单价 ¥8，小杯/中杯/大杯购买数量分别为 1/4/10，价格 ¥8/¥32/¥80。新代码位于 `CoffeePurchaseService.ets`，不依赖业务云或会员会话。

公开配置集中在 `entry/src/main/resources/rawfile/coffee_config.json`：

- `productId`：实际Pro商品为 `buy_coffe`，真实查询已返回¥8单价。
- `appId`：可选的 IAP 订单 App ID 校验值。留空时由官方 SDK 根据签名应用识别商店身份；填写后要求回执 App ID 一致。这不是 OAuth Client ID，也不能代替应用签名。
- `unitPriceCny`：商店查询完成前的展示单价，当前为 8。真实查询成功后展示商店价格；点击时再次检查，价格变化要求刷新后重新点击。

IAP App ID、包名、开发证书/profile、商品及沙盒账号必须属于同一个实际应用。无需在客户端保存任何支付私钥或 Client Secret。仅替换旧柚商品字符串不会把旧柚的商店配置迁移到 Pro。

购买前先查询并核销该咖啡商品的未完成订单；发现旧付费订单时本次不再发起新付款。查询支持分页，忽略其他商品。收银台取消不报成功；核销失败显示待确认并支持重试。SDK `finishPurchase` 成功后显示完成；1001860030/1001860050 仅在官方 UNFINISHED 分页查询确认该订单已消失时按幂等完成处理，仍在列表或查询失败则保留待确认。实际字段为 `applicationId/productType`，核对应用、商品和数量，不能使用旧的 `appId` 字段拒绝正常订单。回执解析只获取官方 SDK 返回的订单引用，用于 SDK 核销，不据此授予云会员。

开发调试自动验证查询、页面及已确认生效的免费官方沙盒；不会自动确认真实扣费。未配置商品或沙盒账号时显示 SDK 的实际结果，不能声称真实付费已验证。

## 会员价格与已保存优惠

公开配置 `value_added_config.json` 的 `membershipPromotionalOfferId` 选择现有优惠 `vip_2026_year_end`，不新增后台活动。会员商品为 `vip_monthly_auto`，标准价 ¥5/月。页面从官方 `queryProducts` 读取优惠价及期数；当前真实返回为前 2 个计费周期每期 ¥2，之后 ¥5/月自动续费。领取截止日期不等于所有订阅在 2027 年统一恢复标准价。

两套皮肤共用会员卡片；仅未开通或已到期用户显示价格、优惠和购买。有效 VIP 显示权益及管理；本期有效但自动续费关闭时，“恢复续订”打开官方管理页，不新购当前月。未登录仍可查询价格，购买权限独立检查。价格或优惠发生变化时要求刷新；优惠签名缺失时不会继续发起原价购买。自定义促销的服务端签名桥接属于必要购买参数，不包含额外日历定价。详见 [现有优惠适配](EXISTING_MEMBER_OFFER_20261013.md)。

## 单份备份

本地每个非 Steam 游戏保留一份最新备份。新备份复制和 SHA-256 校验完成后原子更新 `current-backups.json`，再清理旧数据；失败保留旧备份。旧历史迁移会跳过损坏数据并优先选择最近有效的普通备份，恢复前保护副本不覆盖普通备份。删除游戏保留备份，重新导入不自动开启备份。

恢复以暂存目录、原目录改名和 journal 实现回滚；成功清理临时目录，不再创建历史保护版本。恢复中断期间不更新备份。主机故障注入覆盖提交失败及交换目录前后中断，不能等同于真机断电保证。

云端也只保留最新已发布备份，上传完成后在 CloudDB 事务中替换记录，再删除旧对象。删除失败仍计入已用额度并可重试；冲突和不完整上传不删除原备份。云端这部分已通过主机测试，尚无真实部署验证。
