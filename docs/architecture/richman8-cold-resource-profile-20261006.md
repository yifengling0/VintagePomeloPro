## 启动阶段单独结论

`observe-current-startup`（11:45:21–11:45:52）的截图从健康提示到SOFTSTAR；只记录到0.94FPS采样点，GL聚合193次swap，锁等待769次共0.184ms／最大0.002ms。不能将它当成选人掉帧。

真实继承 ntdll ELF `addr2line` 将 `0x49030/0x4902c` 定位为 `find_file_in_dir`，`file.c:3143`，对应大小写不敏感目录查找。同期CPU用户调用栈多次出现 `NtQueryAttributesFile`／`NtCreateFile` 经这个目录扫描。该线索仅证明启动阶段在做文件路径查找；没有给出其精确墙钟占比，且选人主线程栈更常见NtDelayExecution，**没有把目录扫描推广成全部场景统一根因**。

11:47:57–11:48:29后续段末截图确认主菜单，FPS27.94／57.69／56.91；锁等待216279次共20.199ms，最大0.025ms。

## CPU 证据的限制与下一步

现有Hiperf隐藏大部分leaf IP；离线解析按首个可见用户调用链地址分组，将内核样本保留为未知内核，不把用户caller算成内核执行函数。匿名地址不能全部归为FEX，也不能当精确leaf成本。MSS Timer在首次和重复均有明显采样量，不能据此说首次音频解码就是根因。

真实新OpenGL ELF将 `+0x15b3fc` 定位为 `wow64_glMapBufferRange`（unix_wgl.c:3622），而不是凭改包后旧offset推断锁函数。新增锁计时能记录到，证明对应诊断代码运行；进程maps/env及安装目录hash访问受限，没有报告这些读取成功。

继续用FEX已有的 `LibraryJITNaming`／`GlobalJITNaming` 给转译代码区域提供模块身份，分离游戏、WineD3D、音频库与dispatcher工作，然后才选择具体性能修改。已通过bundle-aware传输及逐字节回读部署 `C:\vp-richman8-jit-trace-20261006.bat`，启用只限该次手动启动，默认保持关闭；不更改代码缓存政策、TSO、SMC或精度。该轮有符号登记开销，只用来定位，不作为新旧FPS对照。

FEX当前Windows CRT将 `/tmp/perf-<WinePID>.map` 当DOS路径。BAT在保持原游戏工作目录后准备当前盘的 `\tmp`，但实际符号文件创建和可读性仍待新进程核查；如果未生成，记录具体原因，不假定已解决符号化。没有自动启动游戏或发送输入。
