## 滚轮问题及修正

原始录屏为用户提供的 4.567 秒视频，列表项反复悬停／选中，页面没有持续滚动。用户最终确认鼠标连接电脑，经 HoKit 投屏操作平板；普通 Wine 的同一投屏滚轮也有问题。该路径收到的是投屏转换后的触摸/左键拖动，不能当作平板实体 AxisEvent 通过与否的证据。按用户最新要求，不做 HoKit 特殊适配，只整改现有 Wine 风格双指滚轮。

沿 ArkUI → InputManager → Wayland → Xwayland → CEF 路径采样发现，旧实现每次滚轮前都发送一条绝对鼠标 motion。Xwayland 24.1.3 在 absolute pointer 和 relative pointer 两个 XI slave 之间切换，滚轮走后者；诊断中表现为 source 6 的滚动轴反复归零，紧接 source 7 的滚动轴递增。移除静止指针的重复 motion 后，平板 CEF 页面开始持续滚动。这支持设备切换导致滚动基线被重置的判断。

修正包含两处：

- C++ 队列用独立的 `PTR_POSITION` 表达滚轮目标位置同步。仅外部绑定 surface 在实际坐标不变时跳过 motion，移动到新位置仍同步；普通 Wine 的轴处理保留。
- ArkUI 实体滚轮入口只更新当前指针记录，位置由上述 native 路径同步，避免在进入滚轮队列之前再次发送无条件 motion。滚轮不通过点击或按钮事件模拟。

保留小数滚动量、方向、同时间戳去重和 END/CANCEL 不重放规则。诊断只记录有界指针数据，不收集键盘文字；不开启 marker 时不运行 X11 observer。

## 实测证据与边界

v75 已安装并通过以下平板操作（系统注入真实双指触摸路径）：

- 商店页面向下连续滚动，停手后再采样页面位置保持；反方向能返回页面上部。
- 游戏库左侧列表从中文条目滚到英文后段，延迟截图保持位置，没有回弹。
- 开启工具栏触摸板后，单指移动虚拟指针到列表，双指分别向上／向下滚动，列表内容随方向变化。
- 直接拖动商店真实滚动条可以定位页面。

v76 在 v75 基础上补齐实体 AxisEvent 入口的重复 motion 修正。用户在该包反馈“没变化”的操作仍为电脑经 HoKit 输入，不代表平板原生双指测试失败，也未证明平板实体蓝牙鼠标通过。

进一步核对发现直接触摸双指没有记录本次手势起点，滚轮使用旧鼠标位置。v76 实机对照中，在 Steam 列表区域双指上滑，日志仍显示之前的 `px=(820,600)`，说明滚动目标与本次手势所在面板不一致。现有 ArkTS 生产处理方法的回归测试先复现此错误，再以以下改动修正：

- 直接触摸在第二根手指落下时，仅记录双指中点；后续滚轮使用该起点，不制造点击或每步绝对 motion。
- DesktopLayer 的旧双指入口也固定手势起点，避免滚动目标跟随手指跨面板变化。
- 虚拟触摸板继续在虚拟光标位置滚动；手指落点不改写其光标位置。

v77 已覆盖安装到 USB 平板，使用原版 ARM64 Linux Steam 完成以下实机对照：

- 无预先点击目标，在游戏库左侧列表直接双指上滑，列表从中文条目滚到英文后段，2 秒后该列表裁剪逐像素一致；反向手势能返回前部。
- 不在右侧补一次鼠标点击，直接在右侧面板双指上滑，滚动目标从左侧锚点变为右侧锚点。右侧滚动条从 `y=324–469` 到 `y=884–1029`，延迟采样保持 `884–1029`。内容图像因封面异步加载存在像素变化，不能用整幅图像相等判断回弹。
- 普通 Wine Explorer 的 C 盘列表双指滚动有内容变化，停手 2 秒后裁剪逐像素一致。
- 关闭该测试 Explorer，返回同一 Steam 窗口；开启虚拟触摸板，单指定位光标后，双指正反方向均能滚动左侧列表，停手 2 秒后裁剪逐像素一致。滚动位置固定在光标 `px=(534,730)`，没有改到双指实际落点。

上述为系统注入双指触摸的设备测试，并非 HoKit 鼠标轮事件验收；仍需用户在平板直接双指操作确认手感。候选结束时恢复直接触摸模式，不保留测试 Explorer 窗口。

## 启动尺寸

Wine 承载窗口按真实 monitor work area 计算：首选 1024×640、保持 16:10，最多占可用宽高的 90%，居中并在小区域等比缩小。宿主报告有效尺寸后才启动 Xwayland，避免固定 1280×800 和宿主尺寸不一致。

平板已确认初始客户端尺寸 1024×640 且主界面正常。尚未完成分屏／更小启动区域以及最大化、全屏来回的实机验收；不能宣称所有窗口布局通过。
