# Deck 入口与竖屏布局

2026-10-20，`main_proton_steamarm64`，基准 `e5c43c4a`，页面回归基准 `native-steam-external-v116`；后续内置程序、Release 和组件恢复验证见文末。

## 入口归属

| 位置 | 保留的操作 |
| --- | --- |
| Deck 左侧栏 | Steam、游戏库、运行中、会员、赞助、设置、经典界面 |
| 经典左侧栏 | 原有游戏分类，以及会员、赞助、系统设置、帮助 |
| 首页 Steam 选项 | 独立页面：组件状态与管理、大屏模式、普通窗口、游戏下载、Steam 账号 |
| Steam 组件页 | 安装与更新、维护；安装后仍需显式点击启动 Steam |
| 系统设置 → 外观 | Deck 界面动画，独立持久化并即时更新 |

会员、赞助只在两套首页的左侧栏各保留一处，不在顶部或游戏库内容区重复放置。会员直达账号与同步并展开会员详情；赞助直达已有赞助组件并展开选项。手机按真实设备类型隐藏相关入口，会员及赞助服务仍校验设备能力；不能因为手机横屏变宽而开放购买。

## 布局

- 组件大图标、维护标签图标和侧栏图标使用独立容器居中。
- 游戏库和运行中滚动容器显式顶部对齐；组件页顶部居中对齐；分类标签靠左。内容少时不再整块居中下沉。
- 竖屏 Steam 首页按纵向布局显示：状态、标题和启动操作位于上方，封面位于下方；不再将横屏的底部操作和右侧封面直接挤入竖屏。
- 平板可用宽度达到 600vp 时，经典主题保留左侧栏；不足宽屏断点时使用 200vp 紧凑侧栏、适配卡片列数和页边距，标题及说明单行省略。手机及更窄的分屏沿用原有导航策略。
- Steam 选项使用普通页面内容和已有页面切换动画，横屏双列、竖屏单列，滚动容器始终从顶部开始。组件入口从侧栏移入此页。手机“更多”统一进入此页。
- 系统返回键先关闭“更多”、退出选项或返回 Steam 首页；进入组件页后返回保留选项页。待启动时拦截返回，避免启动中误退应用。
- 卡片、封面与手机“更多”的动画保留 v114 的弹簧参数。页面隐藏或路由跳转时取消待执行回调；清理状态不再创建新的 UI 动画。
- 组件页异步窗口设置检查页面代次并捕获失败；已经离开的页面不再注册窗口观察器。

## 启动与旋转

Steam 继续使用当前 Wine 桌面的屏幕方向设置，不根据首页方向覆盖用户的桌面配置。默认“自动横屏”会在从竖屏首页启动后切至横屏桌面。

自有 Wine 窗口宿主在收到显示区域变化后，重新设置待确认目标和重试计数，避免旋转后仍向旧区域重试初始窗口位置。仍需两个稳定采样才发布可用尺寸，不使用未确认的中间尺寸启动 Xwayland。

## 内置程序与组件恢复补充验证

- v124 原生 Release 构建使用 `-O2 -DNDEBUG`。此前候选误用 Debug `-O0`；恢复优化后 D3D11 20 次采样平均 89.75 FPS，与设备约 89.9 Hz 的实际 VSync 一致。D3D9 按产品策略使用 WineD3D/VirGL，20 次采样平均 84.72 FPS，未将其写成 DXVK D3D9 验证。
- 修复普通内置工具优先使用精简诊断载荷的问题。普通启动从 Wine 自带完整 smoke 载荷同步；显式 SmokeRunner 才使用诊断载荷。Graphics Smoke 路径指向实际 ARM64 PE。
- 经典首页已实际启动 D3D11/D3D9 立方体、独立图形测试、Winecfg 和控制面板。图形测试内部 FPS 与桌面 HUD 均持续更新，约 83–87 FPS；默认约 20 秒测试正常退出。控制面板仅确认窗口显示，未逐项验收控制项。
- v124 Deck 工具页实机看到立方体、图形测试、Winecfg 等卡片，未出现停用的 VKD3D。D3D12 继续停用；Maleoon 910 平板不满足本产品 DXVK 2.6 的 920+ 策略，本轮不计为 2.6 实测。
- v125 覆盖安装后，组件页通过系统 DOWNLOAD 目录重新发现已安装组件并恢复缺失的私有路径记录，实际显示“Steam 运行组件已就绪”，未重新下载。恢复只重建路径记录，不安装、重置或自动启动 Steam，不创建空的 Steam 组件目录。单测覆盖空目录、符号链接、系统目录不可用以及游戏/存档保留。
- Release 编译、真实载荷路径/PE 架构审计与图形热路径优化参数审计通过。下载/导入/重置、单一游戏库、版本保留、Deck 和窗口宿主回归通过。

## 游戏启动与前台窗口（2026-10-21）

- 游戏启动 URI 派发确认后不再无条件恢复 Steam；派发 ACK 不表示游戏启动成功。打开库、下载与显式任务恢复仍保留原有行为。
- 游戏 splash 或单个窗口销毁不再立即返回 Steam。确认游戏进程结束且全部相关窗口消失后才返回一次；用户切回 Deck、切换其他窗口或产生交互时取消自动返回。
- 游戏前台期间，Steam 后台的尺寸/模式更新使用 `activate=0`；Wine 宿主的激活发布同样遵守前台归属，不反向抢焦点。显式任务恢复不受影响。
- `ncp-exit`、`ipc-death` 和 `proc-zombie` 可证明对应受管进程已结束，但不能证明 Windows 退出码为零。未知退出码继续单独记录，不伪造成功；兼容工具的退出状态与后续 Cloud 完整验收仍待完成。
- Deck、窗口任务、窗口宿主及游戏启动回归覆盖 splash 替换、多窗口关闭、后台尺寸更新、显式恢复和退出次序。

- v134 补充从 Deck 卡片启动的窗口交接：匹配本次 AppID 的实际游戏窗口出现时只恢复一次，避免游戏停在首页后方；用户的新交互、返回或意图超时会取消该次自动恢复。


## v138 前台归属与连续模式切换补充

Steam 的组件准备、冷启动与导航仅能恢复本次仍有效的前台选择；返回首页或选择其他任务会使旧请求失去自动激活权限。Steam 外部会话不再同时走普通 AppSession 的自动提升，普通 Wine 启动保持原有行为。游戏的显式 Play 与进程/多窗口退出交接继续由 HostWindowTasks 管理。

页面恢复按新一次已确认的大屏访问重新开放有界额度，不重放历史错误。实机连续切换仍复现了客户端加载及退出，不能据此宣称大屏往返全部稳定；详见 `RELEASE_STABILITY.zh-CN.md` 的 v136–v138 续验。


## v139 续验

窗口绑定的可选证据写入不会再把磁盘写入异常带出定时器，ENOSPC 回归通过。实机一次大屏返回桌面有黑内容区延迟，随后恢复；游戏另有前台消息不响应的间歇问题，尚不能归因到 Wayland。诊断轮的退出与正式候选复测分开记录，详见 `RELEASE_STABILITY.zh-CN.md`。

当前 v140 已修复独立接口桥的小包传输等待，完成 Release 打包和实际载荷审计；《新仙剑》仍复现 WineD3D 等待与消息超时，Steam 页面加载和反复模式切换仍存在未决问题。详细证据与边界见 RELEASE_STABILITY.zh-CN.md。
