# Linux Steam 窗口缩放

Steam 保留自身的客户区和标题，Wine 的承载 HWND 不添加额外标题栏。普通窗口的边角拖动现在通过 `_NET_WM_MOVERESIZE` 转成现有 compositor 的交互式 resize grab；仅接受经过 PID／窗口代际核验的外部绑定，并在真实左键按下与焦点仍有效时建立抓取。最大化和大屏模式不接受普通边角缩放。

八方向使用按下时的原始矩形和绝对指针增量计算。拖左边或上边时固定对边，不累计窗口自身的位移。尺寸限制与视口分配一致：320×200 至单边 4096，面积至多 8,388,608 像素；松手、窗口销毁和不再适用的显示状态结束抓取。

Wine 应用尺寸后，ArkTS 将真实 HWND 尺寸传回 X11；X11 发布命令序号作为确认。确认前不把旧的普通窗口尺寸写回 Wine，防止拖动后回弹。退出、原生窗口替换及模式切换会结束旧的跟随状态。最终尺寸沿用原有偏好保存，下次启动读取同一份偏好；不改动游戏库。

Steam 的辅助提示窗口在同一 X11 视口内独立处理移动和八方向缩放，遵循 `WM_NORMAL_HINTS` 的最小／最大尺寸；固定大小的提示不强制拉伸。抓取要求真实左键按下，松手或目标撤回即释放。游戏自己的 Wine 窗口仍使用原有的窗口管理流程。

回归使用生产代码，覆盖真实 X11 EWMH 消息、双向尺寸确认、提示窗口及固定尺寸、输入队列释放竞态、八方向几何和面积限制、模式切换、停止与代际变化。主机测试不能替代远端鸿蒙 PC 上使用真实鼠标拖动的验收。
