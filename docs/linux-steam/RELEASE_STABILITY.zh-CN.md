# Linux ARM64 Steam Release 稳定性修复

2026-10-21，分支 `main_proton_steamarm64`，基准 `e5c43c4a`。USB MLR-AL10 平板；手机暂停。保留现有账号、游戏库、存档和配置，使用覆盖安装。

## 已定位问题与处理

1. **Release 支持入口不完整**：将 Steam OHOS host/GNU exec 编译开关固定到源 `entry/build-profile.json5`，避免仅依赖本地构建参数。标准 rawfile 带可重建的自有 Wine 窗口宿主与版本戳；冷启动最多等待 20 秒，取消、早退和迟到结果分别处理。
2. **游戏初始化退出**：补齐独立桥的 kernelbase 会话视图与 PE32/PE64 lsteamclient。修复内部丢弃未注册回调时错误拒绝官方 `Steam_FreeLastCallback=false` 的问题；保留官方 bool 签名和公开返回值。未注册检查、已注册未知回调和不支持 ABI 继续明确失败。
3. **启动时反复切窗**：派发启动 URI 后不再恢复 Steam；splash/单个窗口关闭不当作整个游戏退出；后台尺寸与模式更新不激活 Steam。真实进程结束且全部窗口消失后才允许自动返回，用户的新选择优先。
4. **Deck 发起后游戏在首页后方**：v133 实机重复启动发现的新回归。v134 为显式 Play 请求保留有界意图，仅匹配 AppID 的真实游戏窗口出现后恢复一次 Wine 游戏窗口，不恢复 Steam。支持窗口先于会话关联到达；用户返回首页、交互、主动恢复其他任务或意图超时均取消自动激活。不同 AppID 和旧请求失败不能消费或取消新请求。
5. **换包丢失临时补丁**：四个 Wine 模块、SHA 清单、Wine ZIP/version/manifest、GNU runtime、在线计划及离线包纳入一致性审计。Wine 启动前校验并更新已有 prefix，拒绝覆盖非 Wine builtin 的自定义 kernelbase。没有将 Valve 客户端载荷放入 HAP。

## v136–v138 稳定性续验（2026-10-21）

### 已修复的宿主故障

- 游戏启动服务每 5 秒采集清单/日志，原先 Steam 并发更新文件导致的 list/stat/read 异常会落入服务的致命异常分支，停止全部游戏。现在可选采集与证据写入独立失败；单次 Wine 创建失败只拒绝本请求，后续请求仍可执行。启动控制方已断开时回收刚创建的游戏，不登记无人管理的会话。
- 异步准备组件、冷启动 Wine 和派发导航以前可能在用户已经返回首页或选择其他任务后重新抬起 Steam。现在在操作开始前保存用户选择代次，旧操作可完成后台工作，但失去改变前台的权限。点击已经活动的窗口也取消另一个延迟激活请求。
- AppSessionService 原有外部会话自动提升与 Steam 自有窗口交接重复。Steam 客户端/游戏显式关闭这一条自动提升路径，保留普通 Wine 程序的默认行为。冷启动桌面根窗口同样检查最初的前台意图；用户的显式恢复仍有效。
- Steam 主动退出可能早于退出命令 ACK 被宿主读到。v137 在命令写入后、异步等待前记入 stopping，已停止的同代次会话不再报 ACK 超时；拒绝/超时且客户端仍存活时恢复 running，允许再次退出。
- v138 在确认进入新一轮 Big Picture 时重置该轮页面恢复额度，保留日志游标、去重记录、单轮次数限制与冷却；同一个 CEF 浏览器 PID 被复用时，新一轮模式切换可以恢复。切换本身不会重放旧错误或直接触发导航。

### 验证与限制

- v138 为完整 ArkTS/NDK Release 编译、调试签名覆盖安装。实际 HAP 载荷审计通过，四个 Wine/桥模块与 GNU 对端一致；无 Windows Steam 依赖。Wine ZIP、GNU 组件计划及图形参数沿用此前候选。
- 游戏启动采集失败、控制方断开、单次创建异常、前台选择竞态、普通 Wine 与 Steam 外部会话区别已有回归。共享模型全套通过；本轮后续的退出早于 ACK、退出拒绝/超时重试、同浏览器跨大屏周期恢复回归也通过。独立桥 11 项真实测试此前已运行通过，后续候选桥载荷未变化。
