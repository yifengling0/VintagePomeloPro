# 1.5.1 双 Steam 客户端、离线导入与手机启动复核

分支为 `main_proton_steamarm64`。本轮只操作无线手机，未操作平板；未清理账号、游戏库、Wine 前缀或存档。

## 已定位并修复

1. 离线包此前把完整包身份与宿主适配版本绑定。同一组官方归档在宿主更新后被重新打包，旧包即被拒绝。现在以官方归档集合计算独立身份，复用已有一致 ZIP；安装端仅接收随签名 HAP 固定的整包长度/SHA-256（最多 16 个经过核对的历史身份），解包前验证整包，解包后按当前部署清单逐个校验官方归档。未知或损坏包仍拒绝，未放宽任意 ZIP 导入。
2. 《仙剑四》原先在 `SteamClient014::ConnectToGlobalUser` 返回 `SourceUnverified`。原生 ARM64 客户端与官方库身份正确，但手机上通过另一个进程的 `/proc/<pid>/fd` 枚举无法借到真实对端 socket。新增同 UID、指定 PID 校验的元数据请求，由目标进程枚举自己的 FD，再通过 `SCM_RIGHTS` 返回真实内核 socket 副本。双方复核回环 TCP 端点，保留客户端映像、模块与 PID 校验；未关闭来源验证，也未调用 Windows Steam。
3. 当前待提交集还包含此前完成的 Steamworks ABI/回调与诊断、双客户端选择和隔离、C 盘/Download 存储选择、窗口缩放与模式恢复、后台日志导出，以及 Wine/VirGL/DXVK 打包一致性检查。这些实现按同一配套运行库交付，不能只替换 ArkTS 页面。

## 验证范围

- 手机正常组件页导入已发布的 `hmosdeck-steam-arm64-warning-hook.zip`，完成 12 个组件、5825 个文件，导入后停留组件页，没有自动启动。导入前后 8 个游戏清单 SHA-256 一致。该导入测试使用本轮相同安装器，后续候选仅更新了配套 GNU 来源校验。
- 最终候选正常进入官方 Linux ARM64 Steam 游戏库，《仙剑四》两次显示游戏菜单，菜单中的游戏讯息页可打开；窗口关闭后 Wine 返回 0，Steam 保持运行。未读写存档，未验证完整场景、长期游玩或全部游戏。
- 最终导出证据含 `clientSourceVerified=true`、`peerMatched=true`、真实借用 socket 数 1，保留的 `authenticationVerified=false` 不扩写成已验证所有票据认证。
- 主机测试：来源校验 17 项、桥接 32 项通过；socket 元数据 4 项中 1 项可选 lsof 源码构建测试因未配置固定源码归档而跳过。离线包、下载/导入、客户端选择、游戏启动、托管接口、窗口、Deck、云存档和诊断测试通过。历史已发布包的兼容接收有主机测试；手机实际导入的是上述一个包。
- Release ArkTS/NDK 构建、HAP 运行库闭包和 ZIP 完整性通过。设备候选采用 debug 签名；交付包移用其签名前原始 Release 输出，并确认无签名。
- 主仓库子模块指向没有变化；Mesa、DXVK 现有提交保持。Wine 改动及构建、打包约束通过项目补丁和脚本记录，未产生需要另行更新的子模块指针。

## 启动耗时

最终候选升级后第一次启动：组件配套更新 55.470 秒，Wine 桌面 15.938 秒，窗口准备 4.058 秒，原生客户端就绪 10.041 秒，合计 85.508 秒。组件阶段会复用并校验已安装官方文件及安装新的内置 GNU 适配层；并非每次都下载客户端。配套标记变化也会触发 Wine 资源更新。

同日更新前一次普通启动到原生会话就绪为 12.267 秒，其中组件检查 0.218 秒；这不是最终候选重启测速结果，不能承诺所有后续启动均为该速度。Steam 登录、云同步和用户确认另计，原生会话就绪不代表网页/登录已经完成。《仙剑四》第一次创建进程到创建菜单窗口约 8 秒。
