## 用户操作

经典／Deck → Linux Steam／下载。Deck 侧栏“下载”和选项中的“下载与组件”统一进入本应用的组件管理页，合并重复的组件入口。页面使用“组件状态、客户端功能、维护”三个分区；无论是否已安装，首次打开均显示组件状态。

查看组件状态、安装或导入完成都停留在管理页。只有用户主动点击“启动 Steam”才启动客户端；已有会话时按钮显示“返回 Steam”。选项菜单进入管理页前先关闭，返回 Deck 不再覆盖旧菜单。未安装时点击主屏 Steam 卡片直接转组件管理，不显示正在启动的反馈。

客户端功能中的“游戏下载安装”明确标注“在 Steam 中查看游戏的下载与更新”，该操作由用户主动选择后才打开官方客户端。它与本应用的组件下载分开。

- **在线安装**：从 Valve 官方线路获取固定版本，支持暂停、继续、进度、速度和具体错误。
- **导入本地组件包**：通过系统文件选择器选择配套 ZIP。已安装时也可导入，用于更新当前应用配套版本或修复损坏组件。只读用户选中的包，不移动或删除原文件。
- **维护 → 清空并重置运行组件**：二次确认并等待 Steam 正常退出后，仅清理清单内未被修改的运行文件和已知组件缓存，保留游戏库、账号与存档；未知或被用户修改的文件保留。完成后可重新在线安装或本地导入。

更新、修复、导入和重置共用任务锁；Steam 未退出时拒绝维护，文件选择取消不退出 Steam。安装中的任务必须先暂停并等待暂停完成，才能更换方式。

页面展示内置准备、组件下载、校验、解压安装、启用、完成或具体错误，以及累计下载量、当前速度、当前组件和文件进度。首次安装完成前启动按钮不可用。离开页面保留当前进程内任务；暂停、退出或系统回收后可继续，当前实现不承诺系统后台常驻下载。

大文件以 4 MiB Range 分段获取；验证 Content-Range 起点、总大小。服务器忽略 Range 时仅重新下载当前包；SHA-256 不匹配只重下该包。使用 Valve 官方备用线路，全部沿用相同大小和 SHA-256，不使用项目镜像。下载请求沿用系统代理设置。

平板曾观测到部分包约 11–22 KiB/s，而小包约 114 KB 可在 647 ms 接收；写盘累计耗时仅数毫秒。同网络电脑的三个官方域名 1 MiB Range 请求约 1.2–1.4 秒。因此已确认下载存在设备／请求／线路差异，尚无证据断定是国内 CDN 路由错误。慢速切线和分段续传仍保留，本地导入提供不依赖设备下载速度的替代方式。

## 本地包与游戏保护

标准包 `hmosdeck-steam-arm64-1792110651.zip` 大小为 347,797,947 字节（约 331.7 MiB），SHA-256 为 `7449d8f9b4034310b0970c8b1fbd14c4d018162157442812bbb06c5a5499f626`。包内只有 `bundle-info.json` 与 `archives/<SHA256>.zip`，GNU 使用当前应用自带包。

应用内置 `offline-package.json` 固定整个本地包的版本、大小及 SHA-256。在整包验证通过前不解压；随后再逐个验证官方 ZIP 及文件。版本错误、损坏、空间不足都显示明确错误，不静默转为联网安装。本地导入额外预留外层包复制和解包空间，当前约需 3.8 GiB 可用空间。

所有安装路径仅操作 `releases/<id>/runtime`、固定客户端资源及组件暂存缓存。更新采用临时文件校验后替换；不递归删除 `SteamLinuxARM64` 或 `client`。`library/steamapps`、客户端 `steamapps`、`userdata`、`config` 和未识别文件均不在重置删除清单；经符号链接指向的目标也不清理。清空组件后游戏无需重新下载。

官方 ZIP 原始路径可能带反斜杠，清单保存原始名与规范化名以兼容解压行为。打包时拒绝目录逃逸、重复条目、越界链接、经链接写入和未匹配的 Valve 资源。客户端仅复制固定资源清单，拒绝覆盖 config、userdata、steamapps 等用户目录。最后完成必要文件与运行时检查，才切换 active release。

## 重建

```sh
python3 scripts/build_linux_steam_distribution.py \
  --runtime /path/to/verified/runtime \
  --package-lock /path/to/steam-packages.lock.json \
  --downloads /path/to/verified/official-zips \
  --output /path/to/reused/distribution \
  --project-url rawfile://linux-steam/hmosdeck-gnu-arm64-v1.zip \
  --rawfile-dir entry/src/main/resources/rawfile/linux-steam
```

`deployment.json` 随源码维护；GNU ZIP 是被忽略的生成产物，打包前必须重建／同步，最终 HAP 必须包含两者。打包工具只从已锁定官方包识别客户端文件，自有 ZIP 中不包含 Valve 原始 ELF 或网页资源。构建包装器必须同步此 rawfile 子目录。

本地包必须在同一份清单与官方缓存上生成，并把新生成的 `offline-package.json` 同步进 HAP：

```sh
python3 scripts/build_linux_steam_offline_package.py \
  --plan entry/src/main/resources/rawfile/linux-steam/deployment.json \
  --downloads /path/to/verified/official-zips \
  --output /path/to/hmosdeck-steam-arm64-1792110651.zip \
  --rawfile-dir entry/src/main/resources/rawfile/linux-steam
```

该脚本生成确定性的 ZIP，源官方包大小或 SHA 不符时拒绝发布。客户端仅接受当前 HAP 配套本地包，不能选择任意 Steam 目录、任意 ZIP 或旧版包进行降级。
